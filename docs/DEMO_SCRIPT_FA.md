# اسکریپت دمو ۵ دقیقه‌ای — Shahkar

هدف: در کمتر از ۵ دقیقه مسیر **پول** و مسیر **کانفیگ** را زنده نشان دهید.

ابتدا seed را یک‌بار اجرا کنید:

```bash
docker exec -u shahkar -w /code -e PYTHONPATH=/code \
  shahkar-shahkar-1 python scripts/prepare_demo_seed.py
```

خروجی، یوزر/پسورد و لینک‌ها را چاپ می‌کند.

---

## موجودیت‌های دمو (ثابت)

| نقش | ورود | رمز |
|-----|------|-----|
| مالک (sudo) | همان ادمین فعلی پنل | رمز خودتان |
| نماینده | `demo_reseller` | `DemoReseller1!` |
| کاربر پورتال | `demo_portal` | `DemoPortal1!` |
| پلن | `دمو ارائه` | قیمت ۵۰٬۰۰۰ · ۳۰ روز · ۱۰ گیگ |

پیش‌نیاز سیستم:

- `billing` و `user_portal` روشن
- کارت پلتفرم در System → Commercial ست شده
- درگاه demo خاموش
- پنل فقط از HTTPS (nginx)

---

## ترتیب ارائه (تایمر)

### ۰:۰۰–۰:۴۵ — مالک
1. ورود به پنل با sudo  
2. یک نگاه به Overview (موجودی / وضعیت)  
3. Resellers → نشان دادن `demo_reseller`  
جمله: «هر نماینده کیف‌پول و کاتالوگ خودش را دارد.»

### ۰:۴۵–۲:۰۰ — شارژ نماینده
1. خروج؛ ورود با `demo_reseller`  
2. مالی → شارژ کیف‌پول → **کارت‌به‌کارت** → مبلغ مثلاً ۱٬۰۰۰٬۰۰۰  
3. آپلود یک فیش تست (عکس ساده) → ثبت  
جمله: «نماینده پول را می‌فرستد؛ تا تأیید مالک، کیف‌پول شارژ نمی‌شود.»

### ۲:۰۰–۲:۴۵ — تأیید شارژ (مالک)
1. ورود دوباره با sudo  
2. مالی → سفارش‌ها → تأیید شارژ `demo_reseller`  
3. نشان دادن نوتیف / بج اگر اپ نصب است  
جمله: «تأیید لحظه‌ای؛ نماینده بلافاصله موجودی می‌بیند.»

### ۲:۴۵–۴:۱۵ — سفارش پورتال
1. مرورگر جدا / گوشی: `/portal/` با `demo_portal`  
2. خرید → پلن `دمو ارائه` → پرداخت کارت‌به‌کارت → فیش → ثبت  
جمله: «کاربر نهایی بدون پنل فنی، مثل فروشگاه خرید می‌کند.»

### ۴:۱۵–۴:۴۵ — تأیید سفارش (نماینده)
1. ورود `demo_reseller` → مالی → سفارش‌ها → تأیید  
2. برگشت به پورتال → کانفیگ / وصل شو / لینک ساب  
جمله: «از پرداخت تا کانفیگ، یک جریان کامل.»

### ۴:۴۵–۵:۰۰ — جمع‌بندی
- وایت‌لیبل / دامنه ساب (اگر دارید یک جمله)  
- PWA: «روی گوشی مثل اپ نصب می‌شود و نوتیف سفارش می‌آید.»

---

## اگر وسط دمو چیزی گیر کرد

| مشکل | کار |
|------|-----|
| کارت در شارژ نیست | System → Commercial → فعال‌سازی کارت پلتفرم |
| پلن در پورتال نیست | seed را دوباره بزنید؛ پلن باید `enabled` و مال `demo_reseller` باشد |
| سفارش نمی‌آید | فیش آپلود شده باشد؛ status باید `awaiting_review` باشد |
| پورتال login نمی‌شود | دوباره `prepare_demo_seed.py` |
| نوتیف نمی‌آید | HTTPS + اجازه Notification + اپ نصب‌شده |

---

## بعد از دمو (اختیاری)

اکانت‌های دمو را نگه دارید؛ برای جلسه بعد همان seed را دوباره بزنید تا رمزها ریست شوند.  
حذف کامل لازم نیست مگر محیط مشترک با مشتری واقعی باشد.
