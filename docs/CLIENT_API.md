# SigmaGuard Client API (`/api/v2`)

The client API is the contract between **NexusPanel** (server) and the
**SigmaGuard** app (Flutter UI + Rust core). It is intentionally small and
versioned: the app negotiates protocols, fetches connection material, and
reports network probes so the panel can recommend the best node.

> **Gating.** Every endpoint below is behind the `client_api` feature flag
> (off by default). Enable it from **System → Feature flags** (sudo only).
> Authentication reuses the end-user **portal** credentials, so each app user
> must have `portal_enabled = true` and a portal password set.

## Authentication

Tokens are HS256 JWTs signed with the panel's JWT secret.

| Token | `access` claim | Lifetime |
|-------|----------------|----------|
| access  | `app`         | `JWT_ACCESS_TOKEN_EXPIRE_MINUTES` (0 = never) |
| refresh | `app_refresh` | 30 days |

### `POST /api/v2/auth/login`

```json
// request
{ "username": "alice", "password": "••••••" }
// 200
{
  "access_token": "eyJ…",
  "refresh_token": "eyJ…",
  "token_type": "bearer",
  "expires_in": 86400
}
```

`401` on bad credentials or disabled portal access. Rate-limited by
`LOGIN_MAX_ATTEMPTS` / `LOGIN_MAX_WINDOW_SECONDS`.

### `POST /api/v2/auth/refresh`

```json
// request
{ "refresh_token": "eyJ…" }
// 200
{ "access_token": "eyJ…", "token_type": "bearer", "expires_in": 86400 }
```

All `/client/*` endpoints expect `Authorization: Bearer <access_token>`.

## `GET /api/v2/client/negotiate`

Returns the ordered protocols usable on the caller's current network.

Query params:

| param | values | default |
|-------|--------|---------|
| `profile` | `gamer` \| `trader` \| `normal` | user's stored `client_profile` |
| `net` | `open` \| `restricted` \| `heavily_restricted` | `open` |
| `udp` | `true` \| `false` | `true` |

```json
{
  "profile": "gamer",
  "net": "open",
  "udp": true,
  "usable_protocols": ["amneziawg", "hysteria2", "vless-reality", "wireguard", "shadowsocks-2022"],
  "blocked_protocols": [],
  "recommended": "amneziawg"
}
```

Rules (see `app/client/__init__.py`):

- **gamer** → `amneziawg → hysteria2 → vless-reality` (lowest latency first).
- **trader** → pinned to `vless-reality` only; never auto-switches.
- **normal** → `vless-reality → shadowsocks-2022 → cdn`.
- No UDP → all of `amneziawg / hysteria2 / wireguard` are blocked.
- `heavily_restricted` → only camouflaged protocols (`vless-reality`, `cdn`).

## `GET /api/v2/client/config`

Same query params as `negotiate`, plus optional `country`. Returns the ordered
protocols, the recommended/fallback node, and the user's **real** connection
material (subscription URL + v2ray share links generated by the existing
pipeline).

```json
{
  "profile": "normal",
  "country": "DE",
  "net": "open",
  "recommended_protocol": "vless-reality",
  "recommended_node": 2,
  "fallback_node": 1,
  "protocols": [
    { "priority": 1, "protocol": "vless-reality", "node_id": 2, "node_name": "nl", "region": "eu" }
  ],
  "subscription_url": "https://panel.example/sub/<token>",
  "v2ray_links": ["vless://…", "ss://…"]
}
```

## `POST /api/v2/client/probe`

The app pings candidate nodes and posts measurements. The panel stores them
(`client_probes` table) and returns the best node/protocol.

```json
// request  (?net=open&udp=true)
{
  "profile": "gamer",
  "results": [
    { "node_id": 1, "ping_ms": 38.0, "packet_loss_pct": 0.0, "handshake_ms": 120.0, "protocol_tested": "hysteria2" },
    { "node_id": 2, "ping_ms": 110.0, "packet_loss_pct": 2.0 }
  ]
}
// 200
{
  "recommended_node": 1,
  "recommended_protocol": "amneziawg",
  "fallback_node": 2,
  "fallback_protocol": "hysteria2"
}
```

Node score = `ping_ms + packet_loss_pct * 20` (lower is better); a fresh probe
always beats the node's last known latency.

## `POST /api/v2/client/device-token`

Register/refresh a push token (upsert on `token`). `204` on success.

```json
{ "token": "FCM_OR_APNS_TOKEN", "platform": "android", "app_version": "1.0.0" }
```

`DELETE /api/v2/client/device-token?token=…` unregisters it (e.g. on logout).

## `POST /api/v2/client/telemetry`

Ingest a per-session network-quality sample. `204` on success.

```json
{
  "session_id": "uuid",
  "active_protocol": "hysteria2",
  "active_node": 2,
  "ping_ms": 38.0,
  "packet_loss_pct": 0.2,
  "bytes_sent": 10240,
  "bytes_recv": 204800
}
```

## `GET /api/v2/client/dedicated-ip`

Returns the Trader's pinned static IP (to whitelist on exchanges).

```json
{ "address": "203.0.113.10", "node_id": 2, "assigned": true }
```

When `config` is fetched for a `trader`, the response also carries
`dedicated_ip`, and the recommended node is **pinned** to the node hosting that
IP (no rotation).

### Admin: dedicated-IP pool (`/api/dedicated-ip`, sudo)

| Endpoint | Action |
|---|---|
| `GET /api/dedicated-ip?only_free=` | Pool list + `{total, assigned, free}` |
| `POST /api/dedicated-ip` `{address, node_id?}` | Add an IP to the pool |
| `POST /api/dedicated-ip/assign` `{username}` | Bind a free IP to a user |
| `POST /api/dedicated-ip/release` `{username}` | Return a user's IP to the pool |

## Protocol support & honesty

`negotiate`/`config` only advertise protocols the panel can **actually serve**.
Availability is resolved per request from the live protocol backends
(`app/protocols`) plus node inventory:

| Engine name | Served when… | Status |
|---|---|---|
| `vless-reality` | Xray serves `vless` | live |
| `cdn` (VLESS/ws behind a CDN) | Xray serves `vless` | live |
| `wireguard` | a `core_kind="wireguard"` node exists | live |
| `amneziawg` | a WG node carries AmneziaWG params (`awg_jc…`) | live |
| `shadowsocks-2022` | `shadowsocks` served **and** `client_ss2022` flag on | node-side inbound required |
| `hysteria2` | a backend with `hysteria2` is `available` | requires a second node engine (sing-box) |

Anything not currently serveable is returned in `blocked_protocols`, so the app
never attempts a protocol the backend can't deliver.

### AmneziaWG (obfuscated WireGuard)

Configure obfuscation on a WireGuard node (sudo):

```
PUT /api/node/{node_id}/amneziawg
{ "awg_jc": 4, "awg_jmin": 40, "awg_jmax": 70, "awg_s1": 50, "awg_s2": 100,
  "awg_h1": 1, "awg_h2": 2, "awg_h3": 3, "awg_h4": 4 }
```

Once set, the WireGuard client config emits these keys under `[Interface]` and
`amneziawg` becomes a usable protocol. Clearing all params reverts the node to
plain WireGuard. (Node-side: the node must run the `amneziawg-go`/kernel module
for traffic to actually flow — config generation is panel-side and ready.)

## User profile

`User.client_profile` (`gamer` | `trader` | `normal`, default `normal`) drives
the protocol priority and node policy. When `profile` is omitted from a request
the stored value is used.
